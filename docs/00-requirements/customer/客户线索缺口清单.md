## 1. 任务包概述

### 1.1 任务范围

根据《全CRM差异补齐任务分工与Git协同开发计划》，PKG-01客户线索包由刘焘玮负责，覆盖以下核心业务域：

| 域 | 子模块 | 状态 | 说明 |
|----|--------|------|------|
| 客户域 | 客户管理、联系人管理 | ✅ 基础CRUD已存在 | 增删改查完整，需扩展查重功能 |
| 线索域 | 线索分配与转化 | ✅ 基础CRUD已存在 | 分配转化逻辑完整 |
| 公海域 | 公海机制、领取规则 | ⚠️ 部分存在，需补齐 | 核心接口存在，缺定时任务和记录 |

**不包含范围**：商机成交转订单（OPP-011）属于PKG-02商机产品包，由黄金戈负责。

### 1.2 核心业务流程

```
线索导入 → 创建客户 → 客户跟进 → 商机创建 → 阶段推进
    ↓
超N天无跟进 → 自动掉入公海 → 他人领取 → 重新跟进
```

### 1.3 与其他包的依赖关系

```
PKG-01 客户线索包
    ├── 依赖: PKG-04 配置/权限包 (业务字典、数据权限)
    └── 被依赖: PKG-02 商机产品包 (客户关联、线索转化)
```

### 2.2 差距项详细分析

#### GAP-001：客户自动掉入公海（定时任务）

**需求来源**：SRS CUS-012 / 原型设计：公海管理 → 自动掉入规则

**业务规则**：
- 默认保护期：30天（可配置，通过 `CrmCustomerPoolConfigDO`）
- 保护条件：已成交/已锁定客户不进入公海
- 执行时间：每日凌晨2:00（可配置）
- 掉入后：owner_user_id = NULL，in_sea = 1，记录公海日志

**现有状态**：

| 已有方法 | 文件路径 | 行号 | 说明 |
|----------|----------|------|------|
| `autoPutCustomerPool()` | `CrmCustomerServiceImpl.java` | 435 | 自动放入公海业务逻辑 |
| `putCustomerPool(CrmCustomerDO)` | `CrmCustomerServiceImpl.java` | 456 | 放入公海核心逻辑 |
| `getCustomerPoolConfig()` | `CrmCustomerPoolConfigServiceImpl.java` | 30 | 获取公海配置 |

**缺失内容**：
- ❌ 定时任务触发：`@Scheduled` 或 XXL-JOB 任务类
- ❌ 通知机制：原归属人收到掉入公海通知

**待开发内容**：

| 模块 | 类名 | 方法名 | 说明 |
|------|------|--------|------|
| job | `CrmCustomerAutoDropPoolJob` | `execute()` | 每日凌晨2:00执行自动掉入 |
| service | `CrmCustomerServiceImpl` | `autoPutCustomerPool()` | 完善通知逻辑 |

**API设计**：无需新增API，由定时任务触发

**测试用例**：
| 场景 | 输入 | 预期输出 |
|------|------|----------|
| 正常掉入 | 客户超过30天未跟进，无保护条件 | 客户in_sea=1，owner_user_id=NULL，生成公海记录 |
| 保护期内 | 客户20天未跟进 | 客户状态不变 |
| 已成交保护 | 客户已成交，超过30天 | 客户状态不变 |

#### GAP-002：从公海领取客户（含领取上限）

**需求来源**：SRS CUS-013 / 原型设计：公海管理 → 领取功能

**业务规则**：
- 每日领取上限：10个（可配置）
- 防重复领取：30天内不可重复领取同一客户
- 并发控制：乐观锁（version字段）
- 领取后：客户归属变更为当前用户，in_sea = 0

**现有状态**：

| 已有方法 | 文件路径 | 行号 | 说明 |

| `distributeCustomer()` | `CrmCustomerController.java` | 311 | 分配接口 |
| `validateCustomerExceedOwnerLimit()` | `CrmCustomerServiceImpl.java` | 613 | 客户拥有上限校验 |

**缺失内容**：
- ❌ 每日领取上限校验（按日期统计当天领取数量）
- ❌ 防重复领取规则（查询公海记录判断30天内是否领取过）
- ❌ 并发控制（缺少乐观锁version字段校验）

**待开发内容**：

| 模块 | 类名 | 方法名 | 说明 |

| service | `CrmCustomerServiceImpl` | `receiveCustomer()` | 完善并发控制 |

**API设计**：复用现有 `POST /crm/customer/receive` 接口，内部增加校验逻辑

**测试用例**：
| 场景 | 输入 | 预期输出 |

## 7. 风险与注意事项

| 编号 | 风险描述 | 影响 | 缓解措施 |
|------|----------|------|----------|
| R-001 | 大批量客户掉入公海可能导致锁表 | 高 | 分批处理（每批500条） |
| R-002 | 并发领取同一客户导致数据不一致 | 高 | 乐观锁+分布式锁 |
| R-003 | 查重算法性能问题 | 中 | 索引优化+缓存结果 |
| R-004 | 公海配置变更影响已有规则 | 中 | 配置变更需审批 |
| R-005 | 归属历史数据量大 | 低 | 归档策略+分页查询 |

## 8. 验收标准

| 差距项 | 验收标准 |
|--------|----------|
| GAP-001 | 定时任务每日凌晨2:00执行，符合条件的客户自动掉入公海，原归属人收到通知 |
| GAP-002 | 每日领取数量达到上限后提示；30天内重复领取同一客户被禁止；并发领取仅一人成功 |
| GAP-003 | 有活跃商机时禁止移入；销售经理可移入下属客户并通知 |
| GAP-004 | 名称相似度>80%且手机号相同提示重复；手动查重页面可查询相似客户 |
| GAP-005 | 创建客户时自动查重并弹出提示；确认后仍可创建 |
| GAP-006 | 客户进出公海记录完整保存；支持按客户查询历史记录 |
| GAP-007 | 客户归属变更历史可查询；显示变更前后归属人 |
