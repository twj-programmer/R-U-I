## 5. 逐缺口详细说明

### FIN-GAP-01：回款计划执行状态机

**现状**：`crm_receivable_plan` 表无 `status` 字段；状态通过 `receivable_id` 是否为 NULL 隐式表达。

**目标**：添加明确的执行状态字段，支持以下状态流转：

```
待回款 → 部分回款 → 已回款
   ↘ 已逾期 ↗
```

**改动范围**：
- 数据库：`crm_receivable_plan` 表新增 `status` 字段（tinyint）
- `database/new/` 新增增量 SQL：ALTER TABLE + 字典数据
- 后端：`CrmReceivablePlanDO` 新增 `status` 字段
- 后端：`CrmReceivablePlanServiceImpl` 更新计划状态逻辑（创建回款时更新计划状态、定时任务标记逾期）
- 前端：计划列表页展示状态标签

**验收标准**：
- 创建回款计划时，状态默认为"待回款"
- 关联第一笔审批通过的回款后，状态变更为"部分回款"或"已回款"
- 计划回款日期过期且未完全回款，状态变更为"已逾期"
- 状态变更记录操作日志

---

### FIN-GAP-02：逾期检测逻辑

**现状**：无逾期标记能力。

**目标**：在任何读取回款计划的场景下，动态判断并标记逾期状态。

**改动范围**：
- 后端：`CrmReceivablePlanServiceImpl` 查询方法中增加逾期判断逻辑
- 后端：`CrmReceivablePlanRespVO` 增加 `overdue` 布尔字段
- 前端：列表中逾期计划标红/高亮

**验收标准**：
- `return_time < NOW()` 且 `receivable_id IS NULL`（或状态为"待回款"/"部分回款"）标记为逾期
- 前端列表中逾期计划有明显视觉区分
- 筛选器支持"仅看逾期"过滤

---

### FIN-GAP-03：逾期提醒定时任务

**现状**：`remindTime` 已计算存储，但无消费该字段的后台任务。

**目标**：实现定时任务，每天扫描即将到期和已逾期的回款计划。

**改动范围**：
- 后端：新增定时任务类（可放在 `mitedtsm-module-crm` 或复用 `infra_job` 体系）
- 后端：扫描逻辑——`remind_time <= NOW() AND receivable_id IS NULL AND (status != 已逾期 或 状态为待回款/部分回款)`
- 可能需确认现有 RemindList 组件的数据来源（是实时查询还是有中间表）
- `database/new/` 如有新表则新增 DDL

**验收标准**：
- 定时任务每日执行（建议凌晨）
- 到期/逾期计划出现在前端"回款计划提醒"待办列表中
- 已完全回款的计划不出现在提醒中
- 任务执行日志可追溯

---

### FIN-GAP-04：回款计划金额合计划校验

**现状**：创建回款计划时不检查各期合计。

**目标**：创建/更新计划时，同合同下所有计划的 `SUM(price)` 不得超过合同 `totalPrice`。

**改动范围**：
- 后端：`CrmReceivablePlanServiceImpl.createReceivablePlan()` 和 `updateReceivablePlan()` 中新增校验
- 错误码：新增 `RECEIVABLE_PLAN_TOTAL_PRICE_EXCEEDS_CONTRACT`

**验收标准**：
- 新增计划时，已有各期金额合计 + 新增金额 > 合同总额，则拒绝
- 修改计划金额时同理
- 给出清晰的超限提示（显示剩余可分配金额）

---

### FIN-GAP-05：回款金额与计划偏差提示

**现状**：回款页面自动填充计划金额，但用户可以修改为任意金额，无偏差提示。

**目标**：当实际回款金额与关联回款计划金额偏差超过阈值（如 ±20%）时，给出前端提示（warning，非阻断）。

**改动范围**：
- 前端：`ReceivableForm.vue` 中增加偏差检测和提示
- 可选后端：增加 loose 校验（warning 级别）

**验收标准**：
- 金额偏差 > 20% 时页面显示 warning 提示
- 用户仍可提交（不阻断）
- 操作日志记录偏差情况

---

### FIN-GAP-06：财务数据分析（P1，后移）

**现状**：`deleteReceivablePlan()` 不检查是否有已审批通过的回款关联，只在 update 时有类似约束。

**目标**：如果回款计划已关联审批通过的回款，不允许删除。

**改动范围**：
