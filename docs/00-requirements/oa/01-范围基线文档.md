## 1. 范围定义

### 1.1 总体范围

| 属性 | 内容 |
|------|------|
| **最终目标** | 以现有 CRM 为基线，对照原型补齐已确认的功能差异，形成可运行、可测试、可验收的完整 CRM |
| **范围边界** | CRM 的待办事项、线索、客户、联系人、客户公海、商机、合同、回款、回款计划、产品、数据统计、系统配置，以及与 CRM 直接相关的审批、权限、附件、导入导出和日志能力 |
| **不做的事情** | 不重写已有可复用功能；不新建与现有 CRM 平行的实体、表或接口；不把工单、营销、HR 当作本期 CRM 主线功能开发 |

### 1.2 优先级划分

| 优先级 | 范围 | 对应差异 | 本阶段目标 |
|--------|------|----------|------------|
| **P0** | 权限、客户、联系人、线索、公海、商机、合同/审批、回款/计划、产品、待办、基础配置 | GAP-001~008、010、011 | 跑通 CRM 核心主链：线索 → 客户 → 商机 → 报价 → 合同/审批 → 回款 |
| **P1** | 数据统计、发票/退款/费用的已确认部分 | GAP-009、016 | 完成 CRM 决策数据和已冻结的财务扩展 |
| **后续** | 工单、营销、HR | GAP-012~015 | 保留接口和数据依赖，不占用本期 CRM 资源 |

## 5. 核心主链定义

### 5.1 端到端验收主线

```text
配置角色、数据范围和业务字典
  → 创建客户与联系人
  → 创建或分配线索
  → 将线索转化为客户/商机
  → 为商机添加产品报价并推进阶段
  → 生成或关联合同/订单并发起审批
  → 审批通过后登记回款与回款计划
  → 校验余额、逾期提醒、待办和操作日志
  → 按权限查看销售漏斗、回款和客户归属统计
```

### 5.2 集成顺序

```
权限/租户/基础配置 → 客户+联系人+公海 → 线索分配与转客户 → 商机+产品报价+跟进 → 合同/订单映射+BPM审批 → 回款+回款计划+逾期 → CRM待办+操作日志+附件 → CRM数据统计与导出 → 端到端回归+UAT
```
