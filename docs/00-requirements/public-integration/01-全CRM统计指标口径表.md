## 4. 统一统计规则

| 规则 | 冻结口径 |
|---|---|
| 租户 | 所有统计只能读取当前租户数据，禁止跨 `tenant_id` |
| 逻辑删除 | 默认只统计 `deleted = 0` 的有效记录，关联表也必须应用相同规则 |
| 时间区间 | 开始和结束时间均包含；按日、周、月汇总时必须补齐区间内空时间段 |
| 时间字段 | 每个指标必须明确使用业务时间还是创建时间，不得因实现方便混用 |
| 时区 | 前端、接口、数据库对账统一使用项目部署时区；跨日边界用例必须单独验证 |
| 人员范围 | 指定人员时只统计该人员；指定部门时包含子部门；最终集合必须与当前用户可访问范围取交集 |
| 归属规则 | 客户/商机/合同/回款原则上按对应业务记录的负责人归属，不以创建人替代，例外必须单列 |
| 审批业务 | 合同、回款等受审批控制的金额与数量原则上只统计审批通过记录 |
| 金额 | 数据库存储精度为 `decimal(24,6)`；页面和导出默认显示人民币元、两位小数，汇总后再四舍五入 |
| 数量 | 输出整数；没有数据时为 0，不返回 `null` |
| 比率 | `分子 ÷ 分母 × 100%`；分母为 0 时显示 `--`，接口不得出现 Infinity/NaN |
| 平均值 | 先按有效样本计算平均值，再按指标约定保留小数；无有效样本时显示 `--` |
| 去重 | 涉及客户数、联系人数量时必须写明去重主键，默认按业务主键 `id` 去重 |
| 字典 | 字典值按项目配置显示；空值统一归入“未设置”，未知值保留原值并记录数据问题 |
| 排名 | 默认按指标值降序；同值时按用户编号升序，保证接口、页面和导出顺序稳定 |
| 数据权限 | 页面查询、明细下钻和导出必须使用同一筛选条件、同一人员集合与同一数据权限 |
| 审计 | 指标结果必须能通过明细、SQL 或可复现数据集对账，不能只以页面截图作为公式正确性证据 |

## 5. 查询维度与筛选口径

| 查询项 | 适用范围 | 输入规则 | 验收要求 |
|---|---|---|---|
| `deptId` | 客户、漏斗、画像等 | 页面查询必填；选择部门时含子部门 | 不得超出当前用户可访问部门 |
| `userId` | 客户、漏斗、画像 | 可选；选中后与部门及权限范围取交集 | 无权限人员不得返回数据 |
| `userIds` | 后端权限处理/排行榜等 | 原则上由后端根据权限生成，前端不得借此扩大范围 | 篡改请求不能越权 |
| `times` | 全部时间型统计 | 起止时间必须成对出现，开始不得晚于结束 | 边界日数据只统计一次 |
| `interval` | 客户、漏斗趋势 | 按日/周/月分组；定义必须与前端字典一致 | 空周期补 0，标签连续 |
| 分页 | 漏斗明细或排行榜适用接口 | 页码、页大小遵循公共分页约束 | 分页只影响明细，不改变汇总值 |
| 排序 | 排行榜 | 默认指标值降序、人员编号升序 | 多次请求顺序稳定 |
| 重置筛选 | 全部页面 | 重置后回到页面默认部门、人员、时间范围 | 页面、接口与导出条件一致 |

### 5.1 筛选组合最小验证集

1. 仅部门；
2. 部门 + 单个人员；
3. 部门 + 时间区间；
4. 部门 + 人员 + 时间区间 + 统计周期；
5. 有权部门与无权人员组合；
6. 开始时间等于结束时间；
7. 跨月、跨年和空时间段。

## 12. 统计导出需求口径（阶段 0）

统计导出属于计划中的候选开发方向。本节仅定义需求基线，不代表已经选择该开发项，也不代表已经实现。

| 项目 | 阶段 0 口径 |
|---|---|
| 导出范围 | 只导出当前查询条件和当前用户数据权限内的统计结果 |
| 条件一致性 | 部门、人员、时间、统计周期和排序必须与页面当前查询完全一致 |
| 指标一致性 | 文件中的指标名称、公式、精度、空值和合计必须与本文一致 |
| 文件字段 | 至少包含统计维度、统计周期、指标名称、指标值；具体列由评审冻结 |
| 文件格式 | Excel/CSV 等格式待组长与产品确认，未确认前不作为完成标准 |
| 空数据 | 应返回可识别的空结果或明确提示，不得生成含伪造 0 明细的数据 |
| 权限 | 不得通过直接请求导出无权人员或无权部门数据 |
| 可追溯性 | 导出结果须能依据相同条件通过接口或 SQL 对账 |
| 文件命名 | 应包含业务名称和导出时间，最终规范待确认 |

## 14. 自测与独立测试验收矩阵

| 验收项 | 最低场景 | 通过标准 | 证据 |
|---|---|---|---|
| 公式 | 每类指标至少 1 个固定可对账数据集 | 接口/页面结果与明细或 SQL 一致 | 请求响应 + 对账结果 |
| 筛选 | 部门、人员、时间、周期及组合筛选 | 只返回筛选范围内结果 | 请求参数 + 结果截图/响应 |
| 空数据 | 空人员、空期间、空分组、分母为 0 | 数量为 0、比率/平均值为 `--`、集合为空且前端正常 | 响应 + 页面空状态 |
| 数据权限 | 有权、部分有权、无权、跨租户 | 无越权、无旁路、无导出泄漏 | 不同账号响应对比 |
| 导出（如纳入开发） | 普通、筛选后、空数据、无权限、大数据量 | 文件可打开，字段/数值/权限与页面一致 | 文件 + 对账记录 |
| 边界 | 起止同日、跨月/年、金额精度、同值排行 | 无重复/遗漏，精度和排序稳定 | 响应 + SQL/明细 |
| 异常 | 非法时间、无效人员、超大分页等 | 返回明确错误且无敏感信息 | 错误响应 |
| 集成 | 客户→商机→合同→回款→统计/导出 | 主链状态变化能正确反映到统计 | 集成用例记录 |

测试类型至少覆盖：API、前端功能、权限与数据范围、异常与边界、主链集成。修改到的后端逻辑须补充单元测试或等价自动化验证。

## 15. 质量与度量门禁

| 门禁 | 口径 |
|---|---|
| 功能覆盖率 | `已执行且有证据的确认功能点数 ÷ 本轮确认功能点总数 × 100%`，目标不低于 70% |

| 独立性 | 开发自测不能替代交叉测试或独立测试 |
| 代码覆盖率 | 只有真实工具报告才能称代码覆盖率；本文表格只统计功能覆盖率 |
