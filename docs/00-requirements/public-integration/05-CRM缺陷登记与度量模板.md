## 3. 严重级别定义

| 级别 | 定义 | CRM 例子 | 合入门禁 |
|---|---|---|---|
| 阻断 | 系统或核心流程无法继续，无可行规避 | 无法登录、服务启动失败、数据库初始化失败、主链完全中断 | 必须关闭 |
| 严重 | 核心业务错误、越权、金额错误、数据损坏 | 跨租户数据可见、审批未通过却计入回款、导入覆盖错误客户 | 必须关闭 |
| 一般 | 主要功能部分异常，有规避方法 | 筛选组合错误、导出缺列、错误提示不准确 | 原则上关闭，延期需审批 |
| 轻微 | 不影响主流程的体验或展示问题 | 对齐、文案、非关键格式 | 可带计划延期 |

## 4. 优先级定义

| 优先级 | 处理要求 |
|---|---|
| P0 | 立即处理；阻塞后续测试或发布 |
| P1 | 当前迭代必须修复并复测 |
| P2 | 本迭代争取处理，未处理需责任人和日期 |
| P3 | 优化建议，进入需求池 |

严重级别描述影响，优先级描述处理顺序，两者不能混用。

## 5. 状态流转

```text
新建 → 已确认 → 修复中 → 待复测 → 已关闭
  └────────→ 拒绝（需原因和批准人）
  └────────→ 延期（需版本、责任人和日期）
待复测失败 → 修复中
```

开发者只能提交修复并改为“待复测”；不能自行把自己发现或修复的问题直接关闭。

## 8. 度量公式

| 指标 | 公式 | 目标 |
|---|---|---|
| 缺陷关闭率 | `已关闭缺陷数 / 缺陷总数 × 100%` | 趋势持续上升 |
| P0/P1 缺陷关闭率 | `已关闭P0/P1数 / P0/P1总数 × 100%` | 100% |
| 缺陷重开率 | `重开缺陷数 / 已复测缺陷数 × 100%` | 越低越好 |
| 缺陷有效率 | `(已确认+已关闭) / 已提交缺陷总数 × 100%` | 用于改善缺陷质量，不作个人惩罚 |
| 平均修复时长 | `Σ(待复测时间-确认时间) / 已修复缺陷数` | 按严重级别分别统计 |
| 平均关闭时长 | `Σ(关闭时间-发现时间) / 已关闭缺陷数` | 按阶段比较 |
| 缺陷逃逸率 | `后阶段首次发现缺陷数 / 缺陷总数 × 100%` | 越低越好 |

## 9. 发布门禁检查

- [ ] 阻断和严重缺陷为 0；
- [ ] P0/P1 缺陷关闭率 100%；
- [ ] 所有“待复测”均有原测试人结论；
- [ ] 延期缺陷有版本、责任人、计划日期和批准人；
- [ ] 修复提交号、复测提交号和证据可追溯；
- [ ] 越权、跨租户、金额和数据损坏类问题已进行专项回归；
- [ ] 缺陷数据与覆盖率、测试执行表中的失败用例相互对应。
