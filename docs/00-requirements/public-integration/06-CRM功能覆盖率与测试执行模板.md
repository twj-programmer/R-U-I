## 7. 度量公式

| 指标 | 公式 | 门禁 |
|---|---|---|
| 测试执行率 | `已执行用例数 / 计划用例数 × 100%` | 按阶段设定 |
| P0 用例执行率 | `已执行P0用例数 / P0用例总数 × 100%` | 100% |
| 测试通过率 | `通过用例数 / 已执行用例数 × 100%` | ≥95% |
| 功能测试覆盖率 | `已至少执行1条用例的功能点数 / 确认功能点总数 × 100%` | ≥70% |
| P0 功能覆盖率 | `已覆盖P0功能点数 / P0功能点总数 × 100%` | 100% |
| 证据完整率 | `有有效证据的已执行用例数 / 已执行用例数 × 100%` | ≥90% |
| 自动化覆盖率 | `有自动化且实际运行的功能点数 / 适合自动化的功能点数 × 100%` | 只统计实际运行 |
| 缺陷发现率 | `发现缺陷的已执行用例数 / 已执行用例数 × 100%` | 观察指标，不设惩罚目标 |

计算时：

- `已执行 = 通过 + 失败 + 阻塞`；
- “未执行”和“不适用”不进入已执行；
- 阻塞用例进入已执行率，但不能进入通过率分子；
- 部分覆盖的功能点，只要已有至少一条实际执行结果，可以计入总体功能覆盖率，但必须在矩阵中暴露未测场景。

## 10. 覆盖率门禁检查

- [ ] 功能点基线已经组长/需求确认；
- [ ] P0 用例执行率为 100%；
- [ ] P0 功能覆盖率为 100%；
- [ ] 总体功能测试覆盖率不低于 70%；
- [ ] 测试通过率不低于 95%；
- [ ] 证据完整率不低于 90%；
- [ ] 失败用例均关联缺陷 ID；
- [ ] 阻塞用例均有责任人和解除日期；
- [ ] 跨租户、越权、金额、审批状态和数据损坏场景有专项覆盖；
- [ ] 没有把“已设计但未执行”或“仅有代码未运行”虚报为覆盖。
