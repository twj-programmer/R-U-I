# 全 CRM AI 测试数据需求说明

> 当前角色：度量专员  
> 基线日期：2026-07-14  
> 主责边界：安炳琨负责测试数据方案和生成；姚昱竹负责统计场景、覆盖口径和结果核验  
> 安全原则：AI 只能生成虚构、脱敏、可重复的数据，不得使用真实客户个人信息

## 1. 数据生成目标

AI 测试数据必须同时支持：

1. 客户→联系人→商机→合同→回款的完整主链；
2. 统计指标公式核对；
3. 部门、人员、租户数据权限；
4. 导入、导出、空数据和异常反馈；
5. 审批、赢单/输单、公海、逾期等状态覆盖；
6. 多次初始化结果一致，可按批次清理。

## 2. 建议最小数据规模

| 对象 | 建议数量 | 必须覆盖 |
|---|---:|---|
| 租户 | 2 | 相同业务名称/编号但数据完全隔离 |
| 部门 | 每租户 4 | 总部、两个子部门、一个空部门 |
| 用户 | 每租户 8 | CRM 管理员、经理、销售、财务、审批人、无权限用户 |
| 线索 | 40 | 未转化、已转化、无跟进、不同来源/地区/行业 |
| 客户 | 30 | 未成交、已成交、公海、锁定、无负责人、不同画像字典 |
| 联系人 | 45 | 一客户多联系人、关键决策人、无联系方式 |
| 商机 | 36 | 未结束、赢单、输单、无效；不同阶段和金额 |
| 产品 | 12 | 多分类、多单位、启用/停用、不同价格 |
| 商机产品明细 | 50 | 数量 1、数量大于 1、折扣、零边界 |
| 合同 | 30 | 未提交、审批中、通过、拒绝；跨月跨年 |
| 合同产品明细 | 45 | 验证产品销量必须对数量求和 |
| 回款计划 | 35 | 未回款、已回款、部分回款、逾期、即将到期 |
| 回款 | 40 | 审批通过/未通过、0、部分、全额、超额边界 |
| 跟进记录 | 80 | 多业务类型、多方式、同客户多次跟进 |

## 3. 固定统计断言数据集

为避免只生成随机数据，必须保留一组可手工计算的固定样本：

| 场景 | 固定数据 | 预期断言 |
|---|---|---|
| 合同数量 | 销售 A 在 1 月有 2 份通过、1 份审批中合同 | 1 月合同数量 = 2 |
| 合同金额 | 上述通过合同金额 1000.10、2000.20 | 1 月合同金额 = 3000.30 |
| 回款金额 | 1 月通过回款 500.05、200.00，另有拒绝回款 999 | 1 月回款金额 = 700.05 |
| 客户成交率 | 新增 10 个客户，其中 4 个存在通过合同 | 成交率 = 40% |
| 商机赢单率 | 8 个商机，其中 3 个赢单 | 赢单率 = 37.50% |
| 产品销量 | 合同明细数量分别 1、3、5 | 销量 = 9，而不是记录数 3 |
| 成交周期 | 两客户成交周期分别 10 天、20 天 | 平均成交周期 = 15.0 天 |
| 跟进客户数 | 同一客户 3 条记录，另一客户 1 条 | 跟进次数 4，跟进客户数 2 |

## 4. 时间分布要求

| 时间场景 | 数据要求 |
|---|---|
| 月内 | 同月月初、月中、月末 |
| 跨月 | 1 月 31 日与 2 月 1 日 |
| 闰年 | 2 月 29 日 |
| 跨年 | 12 月与次年 1 月，验证年度边界分组 |
| 边界时刻 | `00:00:00`、`23:59:59` |
| 未来时间 | 计划回款、下次联系、预计成交 |
| 空时间段 | 至少一个完全没有业务数据的月份 |

## 5. 权限和租户数据集

| 角色 | 可见范围 | 必测断言 |
|---|---|---|
| CRM 管理员 | 当前租户全部 CRM 数据 | 可见全部部门，不可见其他租户 |
| 销售经理 | 本人及下属 | 指定其他部门用户不得扩大范围 |
| 销售代表 | 本人/被授权业务对象 | 不能通过 `userIds` 查看他人统计 |
| 财务专员 | 获授权合同、回款 | 能看金额但遵循业务权限 |
| 审批人 | 待审批及授权业务 | 审批权限不自动等于全部统计权限 |
| 无 export 权限用户 | 可查询、不可导出 | 按钮隐藏且接口 403/无权限 |
| 第二租户用户 | 仅第二租户 | 与第一租户同名数据仍完全隔离 |

## 6. 导入导出专项数据

### 6.1 客户导入文件

至少准备以下文件：

1. `customer-valid.xlsx`：10 条合法新客户；
2. `customer-duplicate-no-update.xlsx`：含同名客户，禁止更新；
3. `customer-duplicate-update.xlsx`：含同名客户，允许更新；
4. `customer-invalid-dict.xlsx`：非法来源、级别、行业；
5. `customer-invalid-contact.xlsx`：错误手机号、邮箱、超长文本；
6. `customer-empty.xlsx`：只有表头和空行；
7. `customer-mixed.xlsx`：成功、更新、失败混合；
8. `customer-large.xlsx`：达到约定最大行数。

### 6.2 导出数据

- 包含中文、英文、数字和常用标点；
- 金额包含 0、0.01、999999999.99 和 6 位小数原值；
- 含空字典、空备注、超长名称边界；
- 不同角色导出的行数和字段脱敏结果可预期；
- 空筛选结果仍能生成合法表头文件。

## 7. 异常和数据质量场景

| 编号 | 场景 | 预期 |
|---|---|---|
| AI-E01 | 合同引用不存在客户 | 生成阶段拒绝或导入失败，不写入孤儿数据 |
| AI-E02 | 回款的合同与客户不匹配 | 校验失败 |
| AI-E03 | 负金额、负数量 | 校验失败 |
| AI-E04 | 字典值不存在/已停用 | 明确失败原因 |
| AI-E05 | `deleted=1` 数据 | 页面、统计和导出均排除 |
| AI-E06 | 不同租户关联 | 严格拒绝 |
| AI-E07 | 审批通过但业务时间为空 | 数据质量检查失败 |
| AI-E08 | 商机/合同明细合计与主表不一致 | 标记数据质量缺陷 |
| AI-E09 | 重复客户名称 | 按导入策略更新、跳过或失败 |
| AI-E10 | 同一初始化脚本执行两次 | 不产生不可控重复记录 |

## 8. 生成与导入约束

- 固定随机种子，例如 `crm-ai-seed-20260714`；
- 每条数据带批次标识，建议统一备注前缀 `[AI-CRM-20260714]`；
- 优先通过正式 API/导入接口创建，必须直写数据库时按依赖顺序执行；
- 禁止修改系统内置管理员、正式客户和现有业务数据；
- 生成脚本必须支持清理本批次数据，且清理范围只能命中批次标识；
- 金额统一用十进制定点值，不用浮点随机数；
- 生成完成后由对应模块开发者核验字段、关系和业务状态，不能把 AI 输出直接当作正确数据。
