## 3. 冻结实现口径

1. `statusId` 与 `endStatus` 必须且只能提交一个。
2. 进行中阶段只允许同组向前流转，可跳过中间阶段；禁止同阶段、回退和跨组。
3. 进行中商机可进入赢单、输单、无效任一终态；终态不可通过普通状态接口修改或重开，并保留最后一个 `statusId`。
4. 输单必须提交启用的 `crm_business_lose_reason` 字典编码；赢单不得携带原因或结束说明；无效可携带结束说明。
5. 报价不新增独立报价表，继续复用商机产品行和商机汇总金额字段。
6. `discountPercent` 表示减免比例，范围为 `0~100`，最多 2 位小数。
7. 数量必须大于 0、整数最多 18 位且最多 3 位小数；业务单价必须大于 0、整数最多 18 位且最多 2 位小数；同一报价不得重复提交同一产品。
8. 行金额为 `businessPrice × count`，按 `HALF_UP` 保留 2 位；减免金额为产品合计乘减免比例，最终金额为产品合计减减免金额。
9. 状态、基础资料和报价成功写入后版本号加一；旧版本写入返回版本冲突。

## 5. 功能实现说明

### 5.1 阶段与输单原因

- 请求 VO 增加必填 `version`，并对 `statusId`、`endStatus` 做严格二选一校验。
- Mapper 使用带 `id + version + end_status IS NULL` 条件的更新语句，成功后执行 `version = version + 1`。
- 服务层验证当前阶段和目标阶段属于同一状态组，目标 `sort` 必须大于当前 `sort`。
- 输单原因从系统字典 API 按 `crm_business_lose_reason` 查询，只有存在且启用的编码可写入。
- 状态更新响应返回最新 `version`、阶段、终态、输单原因和结束说明，便于前端立即刷新本地快照。

### 5.2 产品关联与报价金额

- 创建与报价更新使用专用请求 VO，不再信任客户端传入的产品原价、行金额或汇总金额。
- 产品原价从产品主数据读取并写入产品行快照；产品不存在或新加入的产品已停用时拒绝写入。
- 产品行按产品编号去重，数量、业务单价和减免比例在 VO 与服务层双重校验。
- 报价更新在同一事务中先以乐观锁更新商机金额，再删除并重建产品行，避免部分成功。
- 报价响应返回最新版本、产品合计、减免比例、减免金额、商机总额和服务端产品快照。
- 基础资料更新与报价更新已分离，普通更新接口不会覆盖产品和报价字段。

### 5.3 跟进记录联动

- `createFollowUpRecord` 增加事务控制。
- 插入跟进记录前校验客户、商机、线索、联系人或合同主对象是否存在，并拒绝不支持的业务类型。
- 对批量关联的 `businessIds`、`contactIds` 先去重并核对实际存在数量。
- 跟进记录插入、主对象最近/下次跟进信息更新、关联商机与联系人下次跟进时间更新整体提交或回滚。

### 5.4 前端接入

- 状态弹窗只允许选择当前阶段之后的同组阶段，并接入赢单、输单、无效终态。
- 输单时显示必填原因字典和可选说明；无效显示可选说明；提交携带详情中的 `version`。
- 商机表单拆分“保存基础资料”和“保存报价”，报价保存后使用服务端响应覆盖金额与版本。
- 产品原价只读，禁止重复选择产品；停用的历史产品按只读行处理；终态商机的状态和报价入口只读。

## 6. API 契约

| 方法与路径 | 权限 | 主要请求 | 主要响应/约束 |
|---|---|---|---|
| `POST /crm/business/create` | `crm:business:create` | 基础资料、状态组、减免比例、产品项 | 返回商机 ID；服务端确定初始阶段、产品快照和金额 |
| `PUT /crm/business/update` | `crm:business:update` | `id`、`version` 和基础资料 | 返回新版本号；不写报价字段 |
| `PUT /crm/business/update-status` | `crm:business:update` | `id`、`version`，以及 `statusId`/`endStatus` 二选一；输单附原因 | 返回状态快照与新版本；校验流转、终态、字典和并发 |
| `PUT /crm/business/update-quotation` | `crm:business:update` | `id`、`version`、`discountPercent`、`products` | 返回服务端报价快照与新版本；终态不可修改 |
| `POST /crm/follow-up-record/create` | 复用现有 CRM 数据权限 | 现有跟进请求及业务/关联对象编号 | 返回跟进记录 ID；关联校验和联动更新位于同一事务 |
