# D2-CON-01 合同审批入口联调记录

**基线版本**：CRM 阶段 2 统一开发基线 V1.5
**任务分支**：`feature/oa`
**任务负责人**：王文渊
**记录状态**：前端独立改动完成；共享审批和真实环境联调待前置任务合入

## 1. 本任务边界

- 合同页面五态展示、草稿无流程号保护、CRM 待办审批入口和 OA/BPM 联调证据。
- 不修改合同/回款提交服务、共享审批状态转换、数据库字段、SQL、权限名或 BPM 模型。

## 2. 已完成的静态核验与页面改动

| 项目 | 结果 | 证据 |
|---|---|---|
| 合同提交接口 | 保留既有 `PUT /crm/contract/submit?id={id}` | `Web/src/api/crm/contract/index.ts` |
| 审批状态 | 保留既有 CRM 五态字典 `0/10/20/30/40` | 合同列表与 `CRM_AUDIT_STATUS` |
| 草稿保护 | 草稿没有流程号时不显示“查看审批” | `Web/src/views/crm/contract/index.vue` |
| 待办保护 | 合同待办没有流程号时不允许跳转审批详情 | `Web/src/views/crm/backlog/components/ContractAuditList.vue` |
| 流程号类型 | 前端定义为可空字符串，与 BPM 返回和草稿为空的情形一致 | `Web/src/api/crm/contract/index.ts` |

## 3. 联调前置与待验证项

| 前置任务 | 当前作用 | D2-CON-01 后续验证 |
|---|---|---|
| `D2-QA-01` | 提供 CRM 测试底座 | 合同页面、待办、权限与接口测试可重复运行 |
| `D2-APR-01` | 修复共享审批状态、并发提交、数据权限与撤回 `40` | 提交、通过、驳回、撤回与 BPM 待办状态一致 |

在两个前置任务合入前，本任务不得宣布接口、并发、撤回事务或 OA/BPM 真实联调通过。

## 4. 联调验收步骤

1. 以有 `crm:contract:update` 权限的合同负责人创建草稿合同，确认状态为 `0` 且不显示“查看审批”。
2. 调用既有提交接口，确认合同状态进入 `10` 且生成非空 `process_instance_id`。
3. 在 CRM 合同页和 CRM 待办页打开审批详情，确认均跳转到同一 BPM 流程实例。
4. 分别在 BPM 执行通过、驳回和撤回，确认 CRM 合同状态依次为 `20`、`30`、`40`。
5. 使用无合同更新权限、跨租户账号和重复提交请求复测，结果以 `D2-APR-01` 的公开接口测试为准。

## 5. 当前测试结论与风险

- 未执行：CRM 单元/接口测试、BPM 真实联调、并发与事务回滚测试。
