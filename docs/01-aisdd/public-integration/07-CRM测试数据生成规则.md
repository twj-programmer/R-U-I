# 全 CRM 集成测试数据生成规则

> 当前角色：度量专员  
> 制定日期：2026-07-14  
> 适用范围：全组 CRM 主链集成、各域自测、前后端联调、导入校验、权限验证和统计对账  
> 配套数据：`全CRM集成联调数据包.xlsx`

## 1. 生成目标

测试数据必须同时满足可重复、可清理、可对账、可隔离和可追溯五项要求，并支持全组共用的“租户/组织/权限→字典配置→线索→客户/联系人/公海→商机/产品/报价→合同/订单→BPM 审批/待办→回款计划/回款→统计/导出”联调链路。工单和营销作为 P1 支线数据提供，不阻塞 CRM P0 主链。

## 2. 批次与命名规则

| 项目 | 统一规则 | 示例 |
|---|---|---|
| 批次号 | `CRM-IT-日期-序号` | `CRM-IT-20260714-01` |
| 名称前缀 | `[联调-批次短号]`，防止与现有数据重名 | `[联调-0714]星河科技` |
| 外部引用号 | 对象缩写 + 三位序号 | `CUS-001`、`BUS-001` |
| 备注 | 必须写入完整批次号 | `[CRM-IT-20260714-01] 固定断言数据` |
| 随机种子 | 固定为 `crm-it-20260714-v1` | 重新生成结果一致 |
| 时间基线 | 以 `2026-07-14 09:00:00` 为基准 | 跨日/月/年单独偏移 |

## 3. 数据规模与覆盖

| 对象 | 固定联调集 | 扩展压力集 | 必须覆盖 |
|---|---:|---:|---|
| 租户 | 2 | 2 | 同名客户跨租户隔离 |
| 部门 | 4 | 10 | 父部门、子部门、空部门 |
| 用户 | 6 | 30 | 管理员、经理、销售、无权限用户 |
| 业务字典/配置 | 12 | 50 | 客户来源、等级、行业、商机阶段、输单原因等 |
| 线索 | 6 | 1,000 | 未转化、已转化、重复线索、不同负责人 |
| 客户 | 10 | 1,000 | 新增、成交、公海、无数据负责人 |
| 联系人 | 8 | 2,000 | 一客多联系人、主联系人、空联系方式 |
| 公海操作记录 | 5 | 1,000 | 投入、领取、分配、领取上限和越权 |
| 产品 | 6 | 500 | 多分类、多单位、启用/停用、不同价格 |
| 商机 | 8 | 2,000 | 进行中、赢单、输单、无效 |
| 商机产品/报价 | 8 | 3,000 | 数量、折扣、报价确认、金额边界 |
| 合同 | 6 | 2,000 | 审批通过、审批中、拒绝 |
| BPM 审批/待办 | 8 | 3,000 | 提交、驳回、撤回、重提、通过和状态同步 |
| 回款计划 | 6 | 3,000 | 未回、部分回款、已回、逾期和即将到期 |
| 回款 | 6 | 3,000 | 通过、拒绝、部分、跨月 |
| 跟进记录 | 8 | 5,000 | 同客户多次跟进、不同业务类型 |
| 工单/营销支线 | 各 3 | 各 1,000 | 状态、权限、异常和与客户的关联 |

固定联调集用于人工对账，不得随机改变金额和状态；扩展压力集可以按固定种子生成。

## 4. 生成顺序

1. 创建或确认租户、部门、用户和角色；
2. 创建字典与配置依赖；
3. 创建线索并执行线索分配、转客户及重复控制；
4. 创建客户、联系人、公海规则和公海操作记录；
5. 创建产品、产品分类、商机、商机产品和报价；
6. 创建合同、合同产品，提交 BPM 审批并生成 OA 待办；
7. 创建回款计划和回款，验证余额、超额与逾期规则；
8. 创建跟进记录、成员权限及工单/营销 P1 支线数据；
9. 执行页面、接口、权限、状态同步和统计/导出采集；
10. 按预期表对账，记录各域确认人、实际主键和缺陷；
11. 执行批次清理并验证无残留。

不得绕过前置对象直接生成孤儿记录。直接写库仅用于隔离测试环境，优先使用正式 API 或导入接口。

## 5. 字段生成规则

| 字段类型 | 生成规则 | 禁止项 |
|---|---|---|
| 姓名/公司名 | 完全虚构，带批次前缀 | 真实客户或同学个人信息 |
| 手机 | 使用 `1990000xxxx` 测试号段格式 | 真实可联系号码 |
| 邮箱 | 使用 `example.test` 域 | 真实邮箱域名和账号 |
| 金额 | 使用十进制定点值，最多 6 位小数 | 浮点随机导致累计误差 |
| 日期 | 明确时区，覆盖边界日和空月份 | 依赖执行当天的动态日期 |
| 状态 | 只使用系统有效字典值；异常集单独标注 | 把非法值混入正常集 |
| 负责人 | 引用已确认用户编号并记录部门 | 随机生成不存在的用户 ID |
| 关联 ID | 先创建主对象，再回填实际主键 | 跨租户关联或引用软删除对象 |

## 6. 权限与租户规则

- 每条记录必须明确 `tenant_id`、负责人和所属部门；
- 当前租户内的经理只能看到本人及授权范围数据；
- 第二租户建立同名客户，用于确认页面、接口、统计和导出均不串租户；
- 无权限用户必须同时验证页面按钮、接口响应和导出结果；
- `creator` 只作为审计字段，不得代替 `owner_user_id` 做人员统计。

## 8. 质量检查

| 检查 ID | 检查内容 | 通过标准 |
|---|---|---|
| GEN-Q01 | 批次标识完整 | 所有业务对象可按批次定位 |
| GEN-Q02 | 关系完整 | 客户、商机、合同、回款无孤儿记录 |
| GEN-Q03 | 金额正确 | 主从合计和预期值一致 |
| GEN-Q04 | 状态有效 | 正常数据全部可被系统字典解析 |
| GEN-Q05 | 权限隔离 | 无跨部门、跨租户泄漏 |
| GEN-Q06 | 可重复 | 同一批次第二次执行不产生无控制重复 |
| GEN-Q07 | 可清理 | 清理只删除本批次且删除后无残留 |
