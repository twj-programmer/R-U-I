# CRM 导入重复校验规则

> 当前角色：度量专员  
> 制定日期：2026-07-14  
> 当前实现范围：客户 Excel 导入  
> 依据：`CrmCustomerImportExcelVO`、`CrmCustomerServiceImpl#importCustomerList`、`CrmCustomerMapper#selectByCustomerName`

## 1. 当前实现基线

当前客户导入包含 12 列：客户名称、手机、电话、QQ、微信、邮箱、地区、详细地址、所属行业、客户等级、客户来源、备注。

当前代码按“当前租户内客户名称精确相等”查询重复：

1. 不存在同名客户：新增；
2. 存在同名客户且 `updateSupport=false`：失败并返回客户名称已存在；
3. 存在同名客户且 `updateSupport=true`：按原客户 ID 更新；
4. 指定 `ownerUserId` 时，新客户创建 OWNER 权限；为空时进入公海；
5. 每条新增或更新记录写操作日志。

当前实现尚未显式完成名称去首尾空格、大小写/全半角归一、文件内重复预检和手机号/邮箱辅助判重，因此这些行为不能默认为已支持。

## 2. 重复键分层

| 层级 | 重复键 | 处理结论 | 说明 |
|---|---|---|---|
| P0 强重复 | `tenant_id + normalized_name` | 必须拦截或按明确更新策略处理 | 本轮客户导入主键规则 |
| P1 高风险重复 | 同租户手机号相同、名称不同 | 告警，人工确认后导入 | 可能是同公司不同联系人，也可能重复客户 |
| P1 高风险重复 | 同租户邮箱相同、名称不同 | 告警，人工确认后导入 | 不直接自动合并 |
| P2 疑似重复 | 名称相似且地址/电话相同 | 只提示，不自动更新 | 需要人工判断 |
| 非重复 | 不同租户同名客户 | 各自独立允许 | 必须验证租户隔离 |

建议归一化仅用于判重副本，不擅自改变导入原值：去首尾空格、连续空白压缩、英文转小写、全角字符转半角。是否上线须由技术和业务评审。

## 3. 文件内与库内校验顺序

1. 校验文件类型、大小和表头；
2. 给每行保留原始 Excel 行号；
3. 校验客户名称非空及字段格式；
4. 计算名称归一值；
5. 检查同一文件内是否重复；
6. 在当前租户内检查数据库重复；
7. 检查负责人、字典和地区是否有效；
8. 根据 `updateSupport` 决定新增、更新或失败；
9. 返回逐行结果并记录批次审计信息。

## 4. 决策矩阵

| 场景 | `updateSupport` | 预期动作 | 结果代码 |
|---|---:|---|---|
| 文件内首次出现，库内无同名 | false/true | 新增 | `CREATED` |
| 文件内同名第二次出现 | false | 第二条失败，不得新增两条 | `DUP_IN_FILE` |
| 文件内同名第二次出现 | true | 默认仍失败，避免同一批次连续覆盖；如需最后一条生效必须另行确认 | `DUP_IN_FILE` |
| 库内已有同名 | false | 跳过并失败提示 | `DUP_IN_DB` |
| 库内已有同名 | true | 更新原记录，主键不变 | `UPDATED` |
| 名称仅首尾空格不同 | false/true | 建议按归一名称判重 | `DUP_NORMALIZED` |
| 名称大小写/全半角不同 | false/true | 建议告警，是否作为强重复待评审 | `POSSIBLE_DUP` |
| 手机相同、名称不同 | false/true | 告警但不自动覆盖 | `PHONE_WARNING` |
| 不同租户同名 | false/true | 允许新增 | `CREATED` |
| 已逻辑删除同名 | false/true | 是否允许新增由唯一索引/业务规则确认 | `REVIEW_DELETED` |

## 5. 更新保护规则

- 更新必须保留原客户 `id`、租户、创建人和创建时间；
- 空单元格是否覆盖原值必须明确，建议默认“不用空值覆盖已有非空值”；
- `ownerUserId` 的改变属于归属变更，应经过权限和上限校验，不应仅靠普通字段更新完成；
- 已有关联商机、合同、回款的客户不得因名称重复被错误合并；
- 每条更新须记录变更前后值、操作者、文件名、批次和时间；
- 导入失败不得产生半条客户或孤立权限记录。

## 6. 返回结果字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `batch_id` | 是 | 本次导入批次号 |
| `import_time` | 是 | 服务端记录的导入开始时间，统一使用部署时区，不信任客户端传值 |
| `row_no` | 是 | 原始 Excel 行号 |
| `raw_name` | 是 | 原始客户名称 |
| `normalized_name` | 是 | 判重使用名称，仅用于审计 |
| `action` | 是 | CREATED/UPDATED/SKIPPED/FAILED |
| `result_code` | 是 | 机器可读结果码 |
| `message` | 是 | 用户可理解原因 |
| `customer_id` | 条件 | 新增或更新成功后的客户 ID |
| `warning` | 否 | 手机/邮箱/相似名称风险 |

## 7. 必测用例

| 用例 ID | 输入 | 前置数据 | 预期 |
|---|---|---|---|
| DUP-01 | 10 个唯一客户 | 库内无同名 | 全部新增 |
| DUP-02 | 文件内同名两行 | 库内无同名 | 第一条新增，第二条 `DUP_IN_FILE` |
| DUP-03 | 库内已有同名，禁止更新 | 已有客户 | 失败且原记录不变 |
| DUP-04 | 库内已有同名，允许更新 | 已有客户 | 原 ID 更新，数量不增加 |
| DUP-05 | 名称前后带空格 | 已有无空格名称 | 验证当前精确匹配风险及建议规则 |
| DUP-06 | 同手机号不同名称 | 已有相同手机号 | 告警，不自动覆盖 |
| DUP-07 | 不同租户同名 | 第二租户已有 | 当前租户允许新增 |
| DUP-08 | 同一文件连续导入两次 | 第一次已成功 | 第二次结果符合更新开关，不增加无控制重复 |
| DUP-09 | 混合成功、重复、非法字典 | 部分已有 | 逐行反馈准确，成功行策略符合事务约定 |
| DUP-10 | 全部空行 | 无 | 整批失败，提示导入列表为空 |
| DUP-11 | 单行客户名称为空、其他字段有值 | 无 | 该行失败并返回原始行号，不得静默新增；若当前实现过滤则登记反馈缺口 |
| DUP-12 | 手机号格式错误 | 无 | 按冻结后的手机号规则失败并指明字段；当前未校验时登记缺口，不得误判为已通过 |

## 8. 当前缺口

| 缺口 ID | 当前表现 | 风险 | 建议优先级 |
|---|---|---|---|
| DUP-G01 | 结果以客户名称为键，文件内同名失败信息可能相互覆盖 | 行级证据不完整 | P1 |
| DUP-G02 | 未保留原 Excel 行号 | 无法快速定位错误行 | P1 |
| DUP-G03 | 未显式归一客户名称 | 空格、大小写、全半角可能绕过判重 | P1 |
| DUP-G04 | 未显式预检文件内重复 | 同批次结果依赖处理顺序 | P1 |
| DUP-G05 | 更新时空值覆盖和负责人变更规则未冻结 | 可能丢失原值或产生权限不一致 | P0 |
| DUP-G06 | 手机、邮箱只做普通字段，不参与风险提示 | 疑似重复客户无法提前发现 | P2 |
| DUP-G07 | 客户导入当前仅校验名称非空，未见手机号格式校验 | 错误手机号可能进入正式联调数据 | P1 |
| DUP-G08 | 结果未统一返回服务端 `import_time` | 批次审计和耗时追踪不完整 | P1 |
