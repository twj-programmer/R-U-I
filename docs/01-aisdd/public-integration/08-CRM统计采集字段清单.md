# CRM 统计采集字段清单

> 当前角色：度量专员  
> 制定日期：2026-07-14  
> 用途：统一统计接口、测试记录、日报和验收报告的采集字段

## 1. 每次统计执行必须采集的上下文字段

| 字段编码 | 中文名称 | 类型/格式 | 必填 | 来源 | 说明 |
|---|---|---|---|---|---|
| `collection_id` | 采集编号 | string | 是 | 采集程序 | 全局唯一，例如 `STAT-20260714-001` |
| `batch_id` | 数据批次 | string | 是 | 测试数据 | 对应联调数据批次 |
| `metric_id` | 指标编号 | string | 是 | 指标口径表 | 例如 `M-PERF-01` |
| `metric_name` | 指标名称 | string | 是 | 指标口径表 | 不允许使用页面临时简称 |
| `tenant_id` | 租户编号 | bigint/string | 是 | 登录上下文 | 不得从前端任意扩大 |
| `dept_id` | 部门编号 | bigint | 条件 | 查询条件 | 未选部门时记录默认范围 |
| `user_id` | 人员编号 | bigint | 条件 | 查询条件 | 单人员统计时填写 |
| `resolved_user_ids` | 实际人员集合 | array/string | 是 | 后端权限解析 | 记录权限取交集后的人员集合 |
| `time_start` | 开始时间 | ISO datetime | 是 | 查询条件 | 含边界 |
| `time_end` | 结束时间 | ISO datetime | 是 | 查询条件 | 含边界 |
| `interval` | 统计周期 | enum | 条件 | 查询条件 | day/week/month/total |
| `dimension_type` | 维度类型 | enum | 是 | 接口设计 | date/user/dept/status/dict/product |
| `dimension_value` | 维度编码 | string | 是 | 查询结果 | 空字典统一 `UNSET` |
| `dimension_label` | 维度名称 | string | 是 | 字典/用户/部门 | 供页面和导出核对 |
| `numerator` | 分子 | decimal | 条件 | 计算过程 | 比率指标必填 |
| `denominator` | 分母 | decimal | 条件 | 计算过程 | 比率指标必填，可为 0 |
| `metric_value` | 指标值 | decimal | 是 | 查询结果 | 原始精度值 |
| `display_value` | 展示值 | string | 是 | 页面格式化 | 例如 `40.00%`、`--` |
| `currency` | 币种 | string | 条件 | 项目配置 | 金额指标默认 CNY |
| `record_count` | 明细记录数 | integer | 是 | 对账查询 | 与指标值不同，便于排错 |
| `api_path` | 接口路径 | string | 是 | 请求记录 | 记录实际接口 |
| `request_hash` | 请求摘要 | string | 是 | 采集程序 | 同条件请求可比较，不保存敏感令牌 |
| `branch_commit` | 分支/提交号 | string | 是 | Git | 结果可追溯到版本 |
| `collected_at` | 采集时间 | ISO datetime | 是 | 系统时间 | 使用部署时区 |
| `collector` | 采集人/程序 | string | 是 | 执行记录 | 人工时写姓名，自动时写任务名 |
| `evidence_path` | 证据位置 | string | 是 | 执行记录 | 响应、SQL、截图或文件路径 |

## 2. 指标来源字段

| 指标组 | 必采业务字段 | 过滤字段 | 对账字段 |
|---|---|---|---|
| 员工业绩 | 合同/回款 `id`、`owner_user_id`、金额 | 审批状态、业务日期、租户、删除标记 | 合同数、合同金额、回款金额 |
| 客户统计 | 客户 `id`、负责人、创建时间、成交状态 | 部门、人员、时间、权限 | 新增数、成交数、跟进数 |
| 销售漏斗 | 商机 `id`、阶段、结束状态、金额 | 创建时间、负责人、权限 | 商机数、赢单数、状态金额 |
| 客户画像 | 客户地区、行业、级别、来源 | 租户、权限、删除标记 | 各字典分组数与总数 |
| 排行榜 | 负责人、业务主键、金额/数量 | 时间、审批、权限 | 排名值、同值稳定顺序 |
| 产品销量 | 合同产品 `product_id`、`count` | 合同审批、负责人、时间 | `SUM(count)` 与记录数分别采集 |

## 3. 任务与质量度量采集字段

| 分类 | 字段 | 计算口径 |
|---|---|---|
| 任务 | 任务 ID、负责人、计划/实际开始结束、状态、阻塞原因 | 每日按任务状态汇总 |
| 工时 | 日期、人员、任务 ID、计划工时、实际工时 | 偏差 = 实际 - 计划 |
| 缺陷 | 缺陷 ID、严重级别、状态、发现/修复/关闭时间、责任人 | 关闭周期按发现到关闭计算 |
| 测试 | 用例 ID、功能点、执行人、结果、缺陷 ID、证据 | 失败/阻塞/未执行分开统计 |
| 覆盖率 | 确认功能点数、已执行且有证据功能点数 | 功能覆盖率 = 已覆盖 ÷ 总数 |
| 版本 | 分支、提交号、环境、构建号 | 每次测试结果绑定唯一版本 |

## 4. 统计采集流程

| 步骤 | 执行动作 | 输入 | 输出/证据 | 责任人 |
|---|---|---|---|---|
| COL-01 | 冻结指标和查询口径 | 指标 ID、公式、时间字段、权限规则 | 已评审指标清单 | 姚昱竹、组长、对应域负责人 |
| COL-02 | 绑定联调批次与版本 | 数据批次、分支、提交号、环境 | `batch_id`、`branch_commit`、环境记录 | 姚昱竹、技术专员 |
| COL-03 | 解析查询与权限范围 | 部门、人员、时间、当前账号权限 | `resolved_user_ids` 和最终筛选条件 | 后端开发、姚昱竹核验 |
| COL-04 | 执行接口和页面查询 | 固定联调数据、请求参数 | 请求、响应、页面截图 | 开发者/测试人 |
| COL-05 | 采集明细和计算中间值 | 业务主键、状态、金额、分子、分母 | 明细清单、SQL 对账结果 | 姚昱竹、对应域负责人 |
| COL-06 | 与预期值对账 | 实际结果、数据包预期值 | 通过/失败/阻塞结论 | 姚昱竹、交叉测试人 |
| COL-07 | 登记差异和缺陷 | 不一致结果及证据 | 缺陷 ID、责任人、严重级别 | 姚昱竹、质量专员 |
| COL-08 | 修复后重新采集 | 新提交号、相同批次或复测批次 | 新采集记录、复测结论 | 原开发者、原测试人 |
| COL-09 | 汇总项目度量 | 各域采集、任务、缺陷和测试记录 | 覆盖率、质量趋势、交付报告 | 姚昱竹 |

流程控制要求：同一指标复测不得覆盖旧记录，必须生成新的 `collection_id`；对账失败时先区分“数据未按规则生成、模块实现错误、统计口径错误、权限范围错误”四类原因，再决定是否登记缺陷。

## 5. 采集频率与责任

| 数据 | 频率 | 采集人 | 复核人 | 保留证据 |
|---|---|---|---|---|
| 统计接口结果 | 每次自测/联调 | 姚昱竹 | 交叉测试人 | 请求、响应、SQL 对账 |
| 任务与工时 | 每日下班前 | 各责任人 | 姚昱竹 | 任务表、日报 |
| 缺陷 | 状态变化即时 | 发现人/责任人 | 姚昱竹、质量专员 | 缺陷单、复测记录 |
| 覆盖率 | 每个测试阶段结束 | 姚昱竹 | 质量专员 | 用例执行表 |
| 交付趋势 | 每日一次 | 姚昱竹 | 组长 | 燃尽/质量报告 |

## 6. 采集质量规则

1. 同一 `collection_id` 只能出现一次；
2. `time_start` 不得晚于 `time_end`；
3. 比率指标必须同时保留分子和分母；
4. 金额指标必须记录币种和原始精度值；
5. `metric_value` 为 0 与无数据必须区分，无数据显示规则由指标口径表决定；
6. `resolved_user_ids` 必须是部门/人员筛选与当前账号权限的交集；
7. 每条采集记录必须绑定分支/提交号和证据；
8. 采集表不得保存密码、令牌、完整手机号等敏感信息。
