## 四、自动化执行策略与报告方案

### 4.1 测试执行矩阵

根据阶段零测试策略定义的测试分层比例（单元测试40%、接口测试30%、UI自动化测试15%、手工测试15%），设计以下测试执行矩阵：

| 测试类型 | Maven阶段 | 执行插件 | 并行执行 | 失败重试 | 报告格式 | 执行时机 | 预期占比 |
|---------|----------|---------|---------|---------|---------|---------|---------|
| 单元测试 | `test` | Surefire | 是（4线程） | 0次 | JUnit XML + Allure | 开发阶段、CI构建 | 40% |
| 集成测试 | `verify` | Failsafe | 是（2线程） | 1次 | JUnit XML + Allure | 交叉测试阶段 | 30% |
| E2E测试 | `verify` | Failsafe | 否 | 2次 | Allure | 集成测试阶段 | 15% |
| 接口自动化测试 | `verify` | Failsafe | 是（4线程） | 1次 | Allure | 交叉测试阶段 | 30% |

**执行时机说明**：
- **开发阶段**：开发者提交代码前，执行单元测试确保核心逻辑正确
- **CI构建**：代码推送至远程仓库后，自动触发单元测试
- **交叉测试阶段**：执行集成测试和接口自动化测试，验证模块间协作
- **集成测试阶段**：执行E2E测试，验证端到端业务流程

### 4.2 Maven插件配置建议

#### 4.2.1 Surefire插件配置（单元测试）

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-surefire-plugin</artifactId>
    <version>3.2.2</version>
    <configuration>
        <includes>
            <include>**/*Test.java</include>
            <include>**/*Tests.java</include>
        </includes>
        <excludes>
            <exclude>**/*IntegrationTest.java</exclude>
            <exclude>**/*E2ETest.java</exclude>
        </excludes>
        <parallel>methods</parallel>
        <threadCount>4</threadCount>
        <failIfNoTests>false</failIfNoTests>
        <testFailureIgnore>false</testFailureIgnore>
        <argLine>
            --add-opens java.base/java.lang=ALL-UNNAMED
            --add-opens java.base/java.util=ALL-UNNAMED
            -Dspring.profiles.active=unit-test
        </argLine>
        <reportsDirectory>${project.build.directory}/surefire-reports</reportsDirectory>
        <properties>
            <property>
                <name>listener</name>
                <value>io.qameta.allure.junit5.AllureJunit5</value>
            </property>
        </properties>
    </configuration>
</plugin>
```

**配置说明**：
- `parallel`：设置为 `methods`，按测试方法并行执行
- `threadCount`：设置为4，根据CPU核心数调整
- `argLine`：指定测试环境为 `unit-test`，并添加Java模块访问权限
- `reportsDirectory`：指定报告输出目录
- `listener`：配置Allure报告监听器

#### 4.2.2 Failsafe插件配置（集成测试/E2E测试）

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-failsafe-plugin</artifactId>
    <version>3.2.2</version>
    <executions>
        <execution>
            <id>integration-test</id>
            <goals>
                <goal>integration-test</goal>
                <goal>verify</goal>
            </goals>
            <configuration>
                <includes>
                    <include>**/*IntegrationTest.java</include>
                    <include>**/*E2ETest.java</include>
                </includes>
                <parallel>classes</parallel>
                <threadCount>2</threadCount>
                <rerunFailingTestsCount>1</rerunFailingTestsCount>
                <failIfNoTests>false</failIfNoTests>
                <testFailureIgnore>false</testFailureIgnore>
                <argLine>
                    --add-opens java.base/java.lang=ALL-UNNAMED
                    --add-opens java.base/java.util=ALL-UNNAMED
                    -Dspring.profiles.active=unit-test
                </argLine>
                <reportsDirectory>${project.build.directory}/failsafe-reports</reportsDirectory>
                <properties>
                    <property>
                        <name>listener</name>
                        <value>io.qameta.allure.junit5.AllureJunit5</value>
                    </property>
                </properties>
            </configuration>
        </execution>
    </executions>
</plugin>
```

**配置说明**：
- `includes`：仅执行集成测试和E2E测试
- `parallel`：设置为 `classes`，按测试类并行执行（集成测试通常有共享状态）
- `threadCount`：设置为2，避免数据库连接池耗尽
- `rerunFailingTestsCount`：失败重试1次，处理偶发性失败

#### 4.2.3 Allure插件配置（测试报告）

```xml
<plugin>
    <groupId>io.qameta.allure</groupId>
    <artifactId>allure-maven</artifactId>
    <version>2.12.0</version>
    <configuration>
        <reportVersion>2.24.1</reportVersion>
        <allureResultsDirectory>${project.build.directory}/allure-results</allureResultsDirectory>
        <allureReportDirectory>${project.build.directory}/allure-report</allureReportDirectory>
    </configuration>
    <executions>
        <execution>
            <id>generate-allure-report</id>
            <phase>site</phase>
            <goals>
                <goal>report</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

**配置说明**：
- `allureResultsDirectory`：指定Allure结果目录（由JUnit5监听器生成）
- `allureReportDirectory`：指定Allure报告输出目录
- `phase`：绑定到 `site` 阶段，执行 `mvn site` 时生成报告

### 4.3 测试报告聚合方案

#### 4.3.1 报告工具选择

| 工具 | 用途 | 优势 | 适用场景 |
|------|------|------|---------|
| Allure | 综合测试报告 | 美观、可交互、支持多维度分析 | 单元测试、集成测试、E2E测试 |
| JUnit XML | 基础报告 | 标准格式、易于解析 | CI/CD集成 |
| JaCoCo | 覆盖率报告 | 专业覆盖率统计、与Maven深度集成 | 代码覆盖率分析 |

#### 4.3.2 报告输出目录结构

```
${project.build.directory}/
├── surefire-reports/           # Surefire单元测试报告
│   ├── TEST-*.xml              # JUnit XML报告
│   └── *.txt                   # 测试输出日志
├── failsafe-reports/           # Failsafe集成测试报告
│   ├── TEST-*.xml              # JUnit XML报告
│   └── *.txt                   # 测试输出日志
├── allure-results/             # Allure原始结果
│   ├── *.json                  # 测试结果JSON
│   ├── *.txt                   # 测试附件
│   └── environment.properties  # 环境信息
├── allure-report/              # Allure最终报告
│   ├── index.html              # 报告首页
│   ├── data/                   # 报告数据
│   └── widgets/                # 报告组件
└── jacoco/                     # JaCoCo覆盖率报告
    ├── jacoco.exec             # 覆盖率数据文件
    ├── jacoco.xml              # XML格式报告
    ├── jacoco.csv              # CSV格式报告
    └── html/                   # HTML格式报告
        └── index.html          # 覆盖率报告首页
```

#### 4.3.3 报告聚合方式

**方式一：单模块报告（开发阶段）**

```bash
# 执行单元测试并生成Allure报告
mvn test allure:report

# 启动Allure报告服务器
mvn allure:serve
```

**方式二：多模块聚合报告（集成阶段）**

```bash
# 在根目录执行，聚合所有模块测试报告
mvn clean test verify site

# 查看聚合报告
open target/site/allure-maven/index.html
```

**方式三：CI/CD流水线报告**

```yaml
stages:
  - test
  - report

unit-test:
  stage: test
  script:
    - mvn test
  artifacts:
    paths:
      - "**/surefire-reports/"
      - "**/allure-results/"

integration-test:
  stage: test
  script:
    - mvn verify
  artifacts:
    paths:
      - "**/failsafe-reports/"
      - "**/allure-results/"

generate-report:
  stage: report
  script:
    - mvn allure:report
  artifacts:
    paths:
      - "**/allure-report/"
    expose_as: '测试报告'
```

## 五、测试覆盖率目标与收集方案

### 5.1 JaCoCo配置建议

#### 5.1.1 JaCoCo Maven插件配置

```xml
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
    <version>0.8.11</version>
    <executions>
        <execution>
            <id>jacoco-prepare-agent</id>
            <goals>
                <goal>prepare-agent</goal>
            </goals>
            <configuration>
                <destFile>${project.build.directory}/jacoco/jacoco.exec</destFile>
                <propertyName>jacoco.agent.argLine</propertyName>
            </configuration>
        </execution>
        
        <execution>
            <id>jacoco-report</id>
            <phase>verify</phase>
            <goals>
                <goal>report</goal>
            </goals>
            <configuration>
                <dataFile>${project.build.directory}/jacoco/jacoco.exec</dataFile>
                <outputDirectory>${project.build.directory}/jacoco</outputDirectory>
                <formats>
                    <format>html</format>
                    <format>xml</format>
                    <format>csv</format>
                </formats>
                <includes>
                    <include>com/meession/etm/module/crm/**/*.java</include>
                </includes>
                <excludes>
                    <exclude>com/meession/etm/module/crm/dal/mysql/**/*.java</exclude>
                    <exclude>com/meession/etm/module/crm/controller/**/*.java</exclude>
                    <exclude>com/meession/etm/module/crm/convert/**/*.java</exclude>
                    <exclude>com/meession/etm/module/crm/enums/**/*.java</exclude>
                    <exclude>com/meession/etm/module/crm/framework/**/*.java</exclude>
                </excludes>
            </configuration>
        </execution>
        
        <execution>
            <id>jacoco-check</id>
            <phase>verify</phase>
            <goals>
                <goal>check</goal>
            </goals>
            <configuration>
                <dataFile>${project.build.directory}/jacoco/jacoco.exec</dataFile>
                <rules>
                    <rule>
                        <element>PACKAGE</element>
                        <limits>
                            <limit>
                                <counter>LINE</counter>
                                <value>COVEREDRATIO</value>
                                <minimum>0.80</minimum>
                            </limit>
                            <limit>
                                <counter>BRANCH</counter>
                                <value>COVEREDRATIO</value>
                                <minimum>0.70</minimum>
                            </limit>
                        </limits>
                    </rule>
                    <rule>
                        <element>CLASS</element>
                        <limits>
                            <limit>
                                <counter>LINE</counter>
                                <value>COVEREDRATIO</value>
                                <minimum>0.70</minimum>
                            </limit>
                        </limits>
                        <excludes>
                            <exclude>com.meession.etm.module.crm.job.**</exclude>
                            <exclude>com.meession.etm.module.crm.util.**</exclude>
                        </excludes>
                    </rule>
                    <rule>
                        <element>METHOD</element>
                        <limits>
                            <limit>
                                <counter>LINE</counter>
                                <value>COVEREDRATIO</value>
                                <minimum>0.60</minimum>
                            </limit>
                        </limits>
                    </rule>
                </rules>
            </configuration>
        </execution>
    </executions>
</plugin>
```

#### 5.1.2 配置说明

**prepare-agent**：
- `destFile`：指定覆盖率数据输出文件
- `propertyName`：指定agent参数变量名

**report**：
- `dataFile`：指定覆盖率数据文件路径
- `outputDirectory`：指定报告输出目录
- `formats`：指定输出格式（HTML、XML、CSV）
- `includes`：只统计CRM模块代码
- `excludes`：排除Mapper、Controller、Convert、Enums、Framework等非核心逻辑代码

**check**：
- `element`：指定检查级别（PACKAGE、CLASS、METHOD）
- `counter`：指定统计类型（LINE、BRANCH）
- `value`：指定统计指标（COVEREDRATIO表示覆盖率）
- `minimum`：指定最低覆盖率要求

#### 5.1.3 覆盖率目标定义

根据阶段零质量门禁要求（功能测试覆盖率≥70%），结合行业最佳实践，定义以下代码覆盖率目标：

| 覆盖率类型 | 目标值 | 适用范围 | 说明 |
|-----------|--------|---------|------|
| 行覆盖率（Line Coverage） | ≥ 80% | 整个CRM模块 | 衡量代码被执行的比例 |
| 分支覆盖率（Branch Coverage） | ≥ 70% | 整个CRM模块 | 衡量条件分支被覆盖的比例 |
| 类覆盖率（Class Coverage） | ≥ 70% | 核心Service类 | 衡量类被测试覆盖的比例 |
| 方法覆盖率（Method Coverage） | ≥ 60% | 核心Service类 | 衡量方法被测试覆盖的比例 |

#### 5.1.4 覆盖率检查规则

| 规则级别 | 覆盖率类型 | 最低阈值 | 违规处理 |
|---------|-----------|---------|---------|
| PACKAGE | LINE | 80% | 构建失败，阻止代码合并 |
| PACKAGE | BRANCH | 70% | 构建失败，阻止代码合并 |
| CLASS | LINE | 70% | 警告，不阻止构建 |
| METHOD | LINE | 60% | 警告，不阻止构建 |

#### 5.1.5 跳过覆盖率检查的场景

| 场景 | 说明 | 配置方式 |
|------|------|---------|
| 定时任务 | 逻辑简单，通过集成测试验证 | 配置exclude排除 |
| 工具类 | 辅助方法，通过调用方测试覆盖 | 配置exclude排除 |
| Mapper接口 | 由MyBatis自动实现 | 配置exclude排除 |
| Controller | 由集成测试覆盖 | 配置exclude排除 |
| Convert类 | MapStruct自动生成或逻辑简单 | 配置exclude排除 |
| Enum类 | 常量定义，无需测试 | 配置exclude排除 |

| `com.meession.etm.module.crm.job` | 定时任务 | ❌ 否 | 逻辑简单，通过集成测试验证 |
| `com.meession.etm.module.crm.util` | 工具类 | ❌ 否 | 辅助方法，通过调用方测试覆盖 |
| `com.meession.etm.module.crm.dal.redis` | Redis层 | ❌ 否 | 配置常量，无需测试 |

#### 5.2.4 Controller层覆盖率追踪策略（与阶段零接口测试占比30%对齐）

**策略说明**：阶段零定义接口测试占比30%，对应的Controller层覆盖率需通过集成测试单独追踪，不纳入单元测试覆盖率统计。

**追踪方式**：
1. 在集成测试执行时，通过JaCoCo的`prepare-agent`配置收集Controller层代码执行数据
2. 生成独立的Controller层覆盖率报告，单独统计接口测试覆盖情况

**配置示例**：

```xml
<plugin>
    <groupId>org.jacoco</groupId>
    <artifactId>jacoco-maven-plugin</artifactId>
    <version>0.8.11</version>
    <executions>
        <execution>
            <id>jacoco-prepare-agent-integration</id>
            <goals>
                <goal>prepare-agent-integration</goal>
            </goals>
            <configuration>
                <destFile>${project.build.directory}/jacoco/jacoco-it.exec</destFile>
            </configuration>
        </execution>
        
        <execution>
            <id>jacoco-report-integration</id>
            <phase>verify</phase>
            <goals>
                <goal>report-integration</goal>
            </goals>
            <configuration>
                <dataFile>${project.build.directory}/jacoco/jacoco-it.exec</dataFile>
                <outputDirectory>${project.build.directory}/jacoco-it</outputDirectory>
                <formats>
                    <format>html</format>
                    <format>xml</format>
                </formats>
                <includes>
                    <include>com/meession/etm/module/crm/controller/**/*.java</include>
                </includes>
            </configuration>
        </execution>
    </executions>
</plugin>
```

**Controller层覆盖率目标**：

| 覆盖率类型 | 目标值 | 适用范围 | 说明 |
|-----------|--------|---------|------|
| 行覆盖率（Line Coverage） | ≥ 70% | Controller层 | 接口测试覆盖30%，对应Controller层覆盖率要求 |
| 方法覆盖率（Method Coverage） | ≥ 60% | Controller层 | 每个API方法至少被调用一次 |

**覆盖率报告输出**：

```
${project.build.directory}/
├── jacoco/                     # 单元测试覆盖率报告（Service层）
│   └── html/
│       └── index.html
└── jacoco-it/                  # 集成测试覆盖率报告（Controller层）
    └── html/
        └── index.html
```

**与阶段零接口测试占比对齐说明**：
- 阶段零定义接口测试占比30%，对应Controller层覆盖率目标≥70%
- 通过集成测试（`*-IntegrationTest.java`）覆盖Controller层，验证API接口的正确性
- 集成测试覆盖率报告单独统计，不与单元测试覆盖率混算

**与阶段2开发基线对齐说明**：
- 根据《CRM阶段2统一开发基线》，审批状态统一为五态模型（0=草稿、10=审批中、20=审批通过、30=审批驳回、40=已取消），不使用状态5
- 商机状态使用`statusId + endStatus`整数模型（`end_status=NULL`表示进行中，1=赢单，2=输单，3=无效），不使用字符串枚举
- 权限点统一使用现有`query`、`update`权限，不为提交动作新增`submit`权限
- `poolDay`为响应层计算字段，不在DO和数据库表中存储

#### 5.2.3 覆盖率统计命令

**执行测试并生成覆盖率报告**：

```bash
# 执行单元测试，生成覆盖率数据
mvn test jacoco:report

# 执行集成测试，生成覆盖率数据
mvn verify jacoco:report

# 查看HTML报告
open target/jacoco/html/index.html
```

**检查覆盖率是否达标**：

```bash
# 执行测试并检查覆盖率
mvn verify

# 如果覆盖率不达标，会输出类似以下信息：
# [ERROR] Rule violated for package com.meession.etm.module.crm.service: 
#        lines covered ratio is 0.75, but expected minimum is 0.80
```

#### 5.2.4 覆盖率趋势跟踪

**方式一：Jenkins集成（推荐）**

```yaml
pipeline {
    agent any
    
    stages {
        stage('Build') {
            steps {
                sh 'mvn clean verify'
            }
        }
        
        stage('Publish Coverage') {
            steps {
                jacoco(
                    execPattern: '**/target/jacoco/jacoco.exec',
                    classPattern: '**/target/classes',
                    sourcePattern: '**/src/main/java',
                    exclusionPattern: '**/dal/mysql/**,**/controller/**,**/convert/**,**/enums/**'
                )
            }
        }
    }
}
```

**方式二：GitLab CI集成**

```yaml
coverage-job:
  stage: test
  script:
    - mvn verify jacoco:report
  artifacts:
    reports:
      cobertura: '**/target/jacoco/jacoco.xml'
    paths:
      - '**/target/jacoco/html/'
  coverage: '/Total.*?([0-9]{1,3})%/'
```

#### 5.2.5 覆盖率报告解读

**JaCoCo HTML报告包含以下关键信息**：

| 指标 | 含义 | 关注重点 |
|------|------|---------|
| Line Coverage | 行覆盖率 | 核心业务逻辑应达到80%以上 |
| Branch Coverage | 分支覆盖率 | 条件判断应达到70%以上 |
| Complexity | 圈复杂度 | 单个方法不应超过15 |
| Missed Instructions | 未执行的指令数 | 应尽可能减少 |
| Missed Branches | 未执行的分支数 | 应尽可能减少 |

**报告分析策略**：
1. **优先关注Service层**：核心业务逻辑所在，必须达到目标覆盖率
2. **分析未覆盖代码**：识别遗漏的测试场景，补充测试用例
3. **关注复杂方法**：圈复杂度高的方法需要更充分的测试
4. **跟踪覆盖率趋势**：确保每次提交后覆盖率不下降
