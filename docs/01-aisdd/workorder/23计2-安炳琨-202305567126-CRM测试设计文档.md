## 一、测试代码架构设计

### 1.1 项目现有测试目录扫描结论

通过对工作区代码扫描，CRM模块现有测试目录情况如下：

| 项目 | 状态 | 说明 |
|------|------|------|
| `src/test/java` | ❌ 不存在 | CRM模块当前无任何Java测试代码 |
| `src/test/resources` | ✅ 存在 | 包含 `application-unit-test.yaml` 和 `logback.xml` |

**现有测试资源分析**：
- `application-unit-test.yaml` 已配置H2内存数据库（端口无特殊配置）、Redis（端口16379）、MyBatis延迟加载等单元测试优化项
- 项目已引入 `mitedtsm-spring-boot-starter-test` 依赖，包含JUnit 5、Mockito等测试框架
- 项目存在统一的测试基类 `com.meession.etm.framework.test.core.ut.BaseDbUnitTest`，系统模块测试均继承此类

**其他模块测试参考**：
系统模块（`mitedtsm-module-system`）已建立完整的测试结构，测试类命名规范为 `{ServiceImpl}Test`，使用 `@Import` 注解导入被测服务，使用 `@MockitoBean` 注解Mock依赖服务，使用 `randomPojo` 生成测试数据，使用 `assertPojoEquals` 和 `assertServiceException` 进行断言。

### 1.3 基类设计建议

#### 1.3.1 BaseDbUnitTest（单元测试基类）

**核心职责**：
- 提供H2内存数据库环境
- 自动初始化SQL schema
- 提供测试数据生成工具
- 提供统一断言方法

**继承关系**：CRM模块单元测试直接继承项目已有的 `com.meession.etm.framework.test.core.ut.BaseDbUnitTest`

**使用示例**：

```java
package com.meession.etm.module.crm.unit.customer;

import com.meession.etm.framework.test.core.ut.BaseDbUnitTest;
import com.meession.etm.module.crm.service.customer.CrmCustomerServiceImpl;
import org.junit.jupiter.api.Test;
import org.springframework.context.annotation.Import;

import jakarta.annotation.Resource;

import static com.meession.etm.framework.test.core.util.RandomUtils.randomPojo;
import static org.junit.jupiter.api.Assertions.assertNotNull;

@Import(CrmCustomerServiceImpl.class)
public class CrmCustomerServiceImplTest extends BaseDbUnitTest {

    @Resource
    private CrmCustomerServiceImpl customerService;

    @Test
    public void testCreateCustomer() {
        // 使用 randomPojo 生成测试数据
        CrmCustomerDO customer = randomPojo(CrmCustomerDO.class);
        Long id = customerService.createCustomer(customer);
        assertNotNull(id);
    }
}
```

#### 1.3.2 BaseIntegrationTest（集成测试基类）

**核心职责**：
- 加载Spring Boot上下文（基于 `BaseDbAndRedisUnitTest`）
- 提供MockMvc进行HTTP请求测试
- 支持事务回滚（`@Transactional`）
- 提供登录Token获取能力

**设计依据**：项目已存在 `BaseDbAndRedisUnitTest`（`com.meession.etm.framework.test.core.ut.BaseDbAndRedisUnitTest`），集成测试应继承此类而非 `BaseDbUnitTest`，以确保同时拥有内存数据库和Redis支持。

**设计建议**：

```java
package com.meession.etm.module.crm.integration;

import com.meession.etm.framework.test.core.ut.BaseDbAndRedisUnitTest;
import org.junit.jupiter.api.BeforeEach;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.test.web.servlet.MockMvc;

@AutoConfigureMockMvc
public abstract class BaseIntegrationTest extends BaseDbAndRedisUnitTest {

    @Autowired
    protected MockMvc mockMvc;

    protected String adminToken;
    protected String saleToken;
    protected String managerToken;

    @BeforeEach
    public void setUp() throws Exception {
        // 预先获取不同角色的Token
        this.adminToken = obtainAdminToken();
        this.saleToken = obtainSaleToken();
        this.managerToken = obtainManagerToken();
    }

    protected String obtainAdminToken() throws Exception {
        return mockMvc.perform(post("/system/auth/login")
                        .param("username", "admin")
                        .param("password", "admin123"))
                .andExpect(jsonPath("$.success").value(true))
                .andExpect(jsonPath("$.data.accessToken").exists())
                .andReturn()
                .getResponse()
                .getContentAsString();
    }

    protected String obtainSaleToken() throws Exception {
        return mockMvc.perform(post("/system/auth/login")
                        .param("username", "sales01")
                        .param("password", "sales123"))
                .andExpect(jsonPath("$.success").value(true))
                .andReturn()
                .getResponse()
                .getContentAsString();
    }

    protected String obtainManagerToken() throws Exception {
        return mockMvc.perform(post("/system/auth/login")
                        .param("username", "sales_mgr01")
                        .param("password", "mgr123"))
                .andExpect(jsonPath("$.success").value(true))
                .andReturn()
                .getResponse()
                .getContentAsString();
    }
}
```

```java
        });
    }

    public static CrmBusinessDO createBusiness(Long customerId, Integer stage) {
        return randomPojo(CrmBusinessDO.class, o -> {

            o.setStage(stage);

        });
    }
```

### 2.2 请求/响应断言规范

#### 2.2.1 统一断言方式

```java
package com.meession.etm.module.crm.fixture;

import com.meession.etm.framework.common.pojo.CommonResult;
import com.meession.etm.framework.common.util.json.JsonUtils;
import org.springframework.mock.web.MockHttpServletResponse;

import static org.junit.jupiter.api.Assertions.*;

public class CrmAssertUtils {

    public static <T> T assertSuccess(MockHttpServletResponse response) throws Exception {
        String content = response.getContentAsString();
        CommonResult<T> result = JsonUtils.parseObject(content, CommonResult.class);
        assertNotNull(result);
        assertEquals(200, result.getCode(), "响应码应为200");
        assertTrue(result.getSuccess(), "响应应成功");
        return result.getData();
    }

    public static void assertErrorCode(MockHttpServletResponse response, Integer expectedCode) throws Exception {
        String content = response.getContentAsString();
        CommonResult<?> result = JsonUtils.parseObject(content, CommonResult.class);
        assertNotNull(result);
        assertEquals(expectedCode, result.getCode(), "错误码不匹配");
        assertFalse(result.getSuccess(), "响应应失败");
    }

    public static void assertErrorCode(MockHttpServletResponse response, Integer expectedCode, String expectedMsg) throws Exception {
        String content = response.getContentAsString();
        CommonResult<?> result = JsonUtils.parseObject(content, CommonResult.class);
        assertNotNull(result);
        assertEquals(expectedCode, result.getCode(), "错误码不匹配");
        assertEquals(expectedMsg, result.getMessage(), "错误信息不匹配");
        assertFalse(result.getSuccess(), "响应应失败");
    }

    public static void assertFieldNotEmpty(Object obj, String fieldName) {
        assertNotNull(obj, "对象不能为空");
        try {
            java.lang.reflect.Field field = obj.getClass().getDeclaredField(fieldName);
            field.setAccessible(true);
            Object value = field.get(obj);
            assertNotNull(value, fieldName + " 不能为空");
        } catch (Exception e) {
            fail("反射获取字段失败: " + fieldName);
        }
    }
}
```

#### 2.2.2 断言设计样例（创建商机接口）

**场景1：正常创建商机**

```java
@Test
public void testCreateBusiness_success() throws Exception {
    // 准备数据
    Long customerId = createTestCustomer().getId();
    
    // 请求参数
    String requestBody = """
        {
            "customerId": %d,
            "name": "测试商机",
            "stage": 1,
            "amount": 100000.00,
            "winRate": 50
        }
        """.formatted(customerId);

    // 执行请求
    MockHttpServletResponse response = mockMvc.perform(
            post("/crm/business/create")
                    .header("Authorization", "Bearer " + saleToken)
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(requestBody)
    ).andReturn().getResponse();

    // 断言
    Long businessId = CrmAssertUtils.assertSuccess(response);

    // 查询验证
    CrmBusinessDO business = businessService.getBusiness(businessId);
    assertEquals("测试商机", business.getName());
    assertEquals(customerId, business.getCustomerId());
    assertEquals(1, business.getStage());
    assertEquals(BigDecimal.valueOf(100000.00), business.getAmount());
    assertEquals(50, business.getWinRate());
}
```

### 2.4 多角色鉴权设计

基于阶段零测试数据方案中的角色定义，设计以下Token获取方法：

#### 2.4.1 角色Token获取封装

```java
package com.meession.etm.module.crm.fixture;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.MvcResult;
import org.springframework.stereotype.Component;

import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.post;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.jsonPath;

@Component
public class TokenHelper {

    @Autowired
    private MockMvc mockMvc;

    private static final String LOGIN_URL = "/system/auth/login";

    public String getAdminToken() throws Exception {
        return obtainToken("admin", "admin123");
    }

    public String getSaleToken() throws Exception {
        return obtainToken("sales01", "sales123");
    }

    public String getManagerToken() throws Exception {
        return obtainToken("sales_mgr01", "mgr123");
    }

    public String getFinanceToken() throws Exception {
        return obtainToken("finance01", "fin123");
    }

    public String getApproverToken() throws Exception {
        return obtainToken("approver01", "app123");
    }

    private String obtainToken(String username, String password) throws Exception {
        MvcResult result = mockMvc.perform(post(LOGIN_URL)
                        .param("username", username)
                        .param("password", password))
                .andExpect(jsonPath("$.success").value(true))
                .andExpect(jsonPath("$.data.accessToken").exists())
                .andReturn();

        String response = result.getResponse().getContentAsString();
        return extractToken(response);
    }

    private String extractToken(String response) {
        int start = response.indexOf("\"accessToken\":\"") + 15;
        int end = response.indexOf("\"", start);
        return response.substring(start, end);
    }
}
```

### 3.1 跨模块集成点识别

基于P0主链（线索→客户→商机→合同→回款），识别以下跨模块集成点：

| 集成点 | 源模块 | 目标模块 | 数据流向 | 验证目标 | 测试优先级 |
|--------|--------|---------|---------|---------|-----------|
| 线索转客户 | CRM-线索 | CRM-客户 | 线索ID → 创建客户 | 验证线索成功转换为客户，关联关系正确 | P0 |
| 创建商机 | CRM-商机 | CRM-客户/产品 | 客户ID、产品ID → 创建商机 | 验证商机与客户、产品正确关联 | P0 |
| 商机报价 | CRM-商机 | CRM-产品 | 产品ID → 获取产品信息 | 验证报价金额计算正确，折扣上限生效 | P0 |
| 赢单创建合同 | CRM-商机 | CRM-合同 | 商机ID → 创建合同 | 验证赢单后自动创建合同，金额一致 | P0 |
| 合同审批 | CRM-合同 | BPM模块 | 合同信息 → BPM审批流 | 验证审批流程正确触发，状态同步更新 | P0 |
| 回款登记 | CRM-回款 | CRM-合同 | 合同ID → 获取未回款余额 | 验证回款金额不超过未回款余额 | P0 |
| 客户分配 | CRM-客户 | system-用户/部门 | 用户ID、部门ID → 权限校验 | 验证分配后数据权限正确生效 | P0 |
| 公海领取 | CRM-客户 | CRM-公海记录 | 客户ID → 创建公海记录 | 验证领取后客户归属变更，公海记录生成 | P0 |
| 公海掉入通知 | CRM-客户 | system-邮件 | 原归属人 → 发送通知 | 验证公海掉入时通知正确发送 | P1 |
| 操作日志记录 | CRM-全模块 | system-日志 | 操作信息 → 记录日志 | 验证关键操作日志完整记录 | P1 |

### 3.3 外部依赖Mock/Stub策略

#### 3.3.1 Mock策略选择依据

| 依赖类型 | 推荐策略 | 选择依据 |
|---------|---------|---------|
| BPM审批 | `@MockBean` | BPM模块在本期范围内，但审批流程复杂，单元测试中Mock以聚焦CRM业务逻辑；集成测试中使用真实BPM |
| 产品查询 | `@MockBean` | 产品模块在本期范围内，单元测试中Mock；集成测试中真实调用 |
| 用户认证 | 复用现有Token | 系统模块认证能力已成熟，直接使用真实Token |
| 邮件通知 | `@MockBean` | 邮件发送为非核心逻辑，Mock避免实际发送邮件 |
| 定时任务 | 手动触发 | 公海定时任务需验证业务逻辑，手动触发而非等待定时 |
| 操作日志 | 真实调用 | 日志记录为核心审计功能，集成测试中真实验证 |
